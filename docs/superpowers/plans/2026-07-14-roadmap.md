# Roadmap: after v1 streaming lands

Sequenced by dependency + risk. v1 = the streaming flow-odom →
`VISION_POSITION_ESTIMATE` pipeline (`2026-07-13-pipeline-streaming.md`).
File map: `2026-07-14-project-structure.md`.

## 1. Initial-state hardening  *(small, do first)*

Needed for v1 quality **and** all commanding.

- Add `--start_alt`, `--start_yaw` (or a single `--takeoff_json`; recorder already
  writes `takeoff.json`, `vio-recorder-pai.py:389`).
- Fix the cold start: seed `MahonyState` from heading, not `np.eye(3)` (identity is
  a 180° roll singularity for the gravity correction).
- Send `SET_GPS_GLOBAL_ORIGIN(start_lat, start_lon, start_alt)` once at startup.
- No streaming rebuild — small change to `pipeline-streaming.py` + `mavlink_bridge.py`.

## 2. Validation gate  *(cheap, de-risks everything below)*

- On the **batch** `pipeline.py`, confirm DSMAC accept-rate actually rises with
  altitude on a known-failure dataset (design spec's open Exp10 question).
- No streaming code needed.
- **Gate:** only build V2b's climb loop (step 5) if this passes. If it fails, the
  repeated-failure response becomes loiter/alert, not climb.

## 3. Layer 1 — DSMAC to streaming  (`streaming/dsmac_live.py`)

- Import DSMAC funcs from `pipeline.py` unchanged.
- Two live problems: ortho-tile **pre-fetch** around start_lat/lon (flight footprint
  unknown ahead of time), and a **worker thread** so GPU matching doesn't stall the
  `VISION_POSITION_ESTIMATE` heartbeat.
- Baro-only depth degrades DSMAC warp scale — carried over from v1's known ceiling.

## 4. V2a — commanding  (`SetpointSender` in `mavlink_bridge.py`)

- Offboard goto-latlon: target lat/lon → local ENU → NED →
  `SET_POSITION_TARGET_LOCAL_NED` every loop (>2 Hz).
- Startup: `wait_heartbeat` → `set_gps_global_origin` → prime setpoints → OFFBOARD.
- Operator flips OFFBOARD in QGC for first bring-up; no auto mode-switch yet.

## 5. V2b — climb-and-search  (`streaming/commander.py`)

- Depends on Layer 1 (DSMAC live) + V2a (commanding) + step 2 passing.
- FSM: NORMAL → SEARCH → GIVE-UP. Consecutive-reject counter reuses the accept flag
  in `pipeline.py`'s `fixes` list.
- Safety bounds (pipeline-side, independent of PX4): bounded climb rate, hard
  altitude ceiling, give-up (hold last fix, stop climbing, alert) on ceiling/timeout.

## Dependency summary

```
1 initial-state ─┐
                 ├─► 4 V2a ─┐
2 validate ──────┼──────────┼─► 5 V2b   (5 only if 2 passes)
3 DSMAC live ────┴──────────┘
```

Steps 1 and 2 need no streaming code and can start immediately in parallel with v1.
